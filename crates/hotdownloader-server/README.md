此 crate 组装共享 Rust 核心，管理任务队列、下载文件、QQ 凭据和进度广播。
浏览器重新连接时可获取当前任务快照，继续查看进度。

## 启动服务

### Docker 启动

将仓库根目录的 [`.env.example`](../../.env.example) 复制为 `.env`，修改用户名和密码，并配置容器内下载目录：

```dotenv
AUTH_USERNAME=admin
AUTH_PASSWORD=请替换为密码
HOTDOWNLOADER_DOWNLOAD_DIR=/downloads
```

拉取镜像并启动服务：

```bash
docker pull ghcr.io/lerdb/hotdownloader:latest
docker run -d --name hotdownloader --restart unless-stopped \
  --env-file .env -p 127.0.0.1:8787:8787 \
  -v hotdownloader-data:/data \
  -v hotdownloader-downloads:/downloads \
  ghcr.io/lerdb/hotdownloader:latest
```

在服务器本机访问 `http://127.0.0.1:8787`，输入 `.env` 中的用户名和密码。
也可只设置 `HOTDOWNLOADER_TOKEN`（至少 16 个字符），继续使用令牌登录。
若同时设置账号密码和令牌，服务只接受账号密码。
Docker 仅将端口绑定到宿主机回环地址，容器内服务仍监听 `0.0.0.0:8787`，以便端口映射正常工作。

从其他设备访问时，请在宿主机配置 HTTPS 反向代理，将请求转发到 `127.0.0.1:8787`，并通过 HTTPS 域名打开网页。
不要将访问凭据通过公网明文 HTTP 传输。

下载任务由服务进程持续执行。重新打开网页即可查看进度。
页面顶部显示服务连接状态和最近响应时间。

### Compose 启动

使用仓库根目录的 [`compose.yaml`](../../compose.yaml)。
在该目录保存 `.env` 后运行：

```bash
docker compose pull
docker compose up -d
```

### 本机启动

从仓库根目录运行：

```bash
cargo run --manifest-path crates/hotdownloader-server/Cargo.toml
```

### 镜像与版本

- 地址：`ghcr.io/lerdb/hotdownloader`
- 架构：`linux/amd64`
- `latest`：随 `main` 分支发布更新
- 版本标签：`vX.Y.Z`、`X.Y.Z`、`X.Y` 和 `sha-<短提交号>`

## 修改配置

网页设置页用于修改下载音质、并发数、命名规则和 QQ 登录凭据。服务监听、访问认证、数据目录与日志级别通过以下环境变量配置。

### 环境变量

| 环境变量 | 用途与默认值 |
| --- | --- |
| `HOTDOWNLOADER_DATA_DIR` | 数据目录，默认 `./data`。 |
| `HOTDOWNLOADER_BIND` | 监听地址，默认 `127.0.0.1:8787`。 |
| `AUTH_USERNAME`、`AUTH_PASSWORD` | 对外监听时可同时设置，启用账号密码认证。`/api` 请求使用 HTTP Basic 认证；两者优先于令牌。不允许只设置其中一个，用户名不能包含冒号。 |
| `HOTDOWNLOADER_TOKEN` | 未设置账号密码时，对外监听需设置至少 16 个字符的访问令牌。`/api` 请求使用 `Authorization: Bearer <token>`。 |
| `HOTDOWNLOADER_WEB_DIR` | 前端构建产物目录，默认 `./dist`。 |
| `HOTDOWNLOADER_DOWNLOAD_DIR` | 下载文件的绝对目录。本机或直接使用镜像时默认是数据目录下的 `downloads`；仓库的 Compose 配置默认是 `/downloads`。 |
| `HOTDOWNLOADER_SCAN_DIRS` | 附加扫描目录，默认 `[]`。详见[挂载已有音乐库](#挂载已有音乐库)。 |
| `HOTDOWNLOADER_DOWNLOAD_MOUNT_MARKER` | 可选的下载盘标记文件，相对于下载目录，如 `.hotdownloader-mounted`；默认不设置。 |
| `HOTDOWNLOADER_LOG_LEVEL` | 日志级别，可设为 `off`、`error`、`warn`、`info`、`debug` 或 `trace`，默认 `info`。 |

### Compose 下载目录

Compose 默认使用独立的 `hotdownloader-downloads` 卷。
如需改用宿主机目录，在 `.env` 中加入：

```dotenv
HOTDOWNLOADER_DOWNLOAD_MOUNT=/srv/music
```

`HOTDOWNLOADER_DOWNLOAD_MOUNT` 控制挂载源。
如需更改容器内路径，再将 `HOTDOWNLOADER_DOWNLOAD_DIR` 设为绝对路径，Compose 会用它作为挂载目标。

### 应用配置变更

Compose 部署修改 `.env` 或 `compose.yaml` 后运行 `docker compose up -d`，让容器应用新配置。额外环境变量需要在 Compose 的 `environment` 中传入；修改日志级别也按此方式处理。

`docker run` 部署修改环境变量或挂载后，按[更新服务](#更新服务)中的方式重新创建容器。本机运行时设置环境变量后重新启动服务。

已有音乐库的只读挂载和目录解析配置见[挂载已有音乐库](#挂载已有音乐库)。

## 数据与重启恢复

### 数据与下载目录

容器使用两个独立的卷：

- `hotdownloader-data` 挂载到 `/data`，保存设置、QQ 凭据和任务记录。
- `hotdownloader-downloads` 挂载到 `/downloads`，保存新下载的文件。

如需使用宿主机目录，将第二个 `-v` 改为：

```text
-v /srv/music:/downloads
```

`HOTDOWNLOADER_DOWNLOAD_DIR` 应与容器内的下载目录挂载目标一致。

从旧版 Docker 部署升级时，已有下载文件仍位于 `hotdownloader-data` 卷中的 `/data/downloads`，已有任务记录也继续引用该路径。
新任务将写入独立的下载卷。请保留原数据卷，以便访问历史文件。

### 数据文件

数据目录包含：

- `settings.json`：下载设置
- `qq-credentials.json`：QQ 登录凭据
- `tasks.json`：任务记录
- `library.sqlite3`：增量文件索引、监控配置、歌单成员快照和以 MID 为键的处理台账

首次启动使用默认设置和空任务列表。
请持久化整个数据目录并限制其访问权限，妥善保护 QQ 凭据和访问令牌。

### 任务恢复

服务进程重启后的任务处理方式：

- **手动任务**：未完成的任务显示在“已中断”标签中，点击恢复后重新入队。
- **监控任务**：未完成的任务自动恢复。
- **主动暂停的监控任务**：保留暂停决定，可在任务页手动恢复。

### 备份与存储异常

- 持久化 `/data`，其中的 `library.sqlite3` 无需独立数据库服务。
- 备份时先停止服务，再复制数据目录，保留任务与台账的一致状态。
- 数据库写入失败会停止新的自动派发，修复存储后重启服务。

### 访问安全

远程访问请使用上述 HTTPS 反向代理，保护浏览器与服务之间的访问凭据。
当前部署使用一组账号密码或单个访问令牌，适合单管理员使用。

## 本地音乐库

### 挂载已有音乐库

下载目录自动纳入扫描，使用下载设置中的命名模板和歌手分隔符。
其他目录通过 `HOTDOWNLOADER_SCAN_DIRS` 配置，值为 JSON 对象数组。

只使用音频标签时，可在 `.env` 中添加：

```dotenv
HOTDOWNLOADER_SCAN_DIRS='[{"path":"/music/archive"}]'
```

然后在 `compose.yaml` 的 `volumes` 中增加对应只读挂载：

```yaml
- /srv/music/archive:/music/archive:ro
```

多个目录需要不同模板时，也可直接在 Compose 服务中配置。
以下内容合并到 `services.hotdownloader`，保留已有配置和挂载：

```yaml
environment:
  HOTDOWNLOADER_SCAN_DIRS: >-
    [
      {
        "path": "/music/archive",
        "template": "{song} - {artist}",
        "artistSeparator": "、"
      },
      {
        "path": "/music/albums"
      }
    ]
volumes:
  - /srv/music/archive:/music/archive:ro
  - /srv/music/albums:/music/albums:ro
```

### 目录配置与模板

目录配置字段：

| 字段 | 含义 | 默认行为 |
| --- | --- | --- |
| `path` | 容器内绝对路径 | 必填 |
| `template` | 文件名解析模板 | 未设置时只读取音频标签 |
| `artistSeparator` | 歌手字符串分隔符 | `、` |
| `mountMarker` | 挂载盘内标记文件的相对路径，不允许 `..` 或指向目录外 | 未设置时使用文件数量骤减保护 |

**模板规则：**

- 必须各包含一次 `{song}` 和 `{artist}`。
- 可加入 `{album}`、`{quality}`，变量之间必须有分隔文字。
- 歌手字符串按目录配置的分隔符拆分，多值歌手标签合并为集合。
- 下载目录的模板若不足以解析标题和歌手，则只使用标签。

### NAS 挂载保护

未配置标记时，每个目录的音频数量比上次成功索引减少 **80% 或更多**（包括从非空变为空），本轮扫描失败，保留原索引并停止本轮监控派发。失败不会重置数量基线，恢复文件后可重新扫描。

NAS 建议预先在实际挂载盘内创建普通标记文件，再配置 `mountMarker`，例如：

```dotenv
HOTDOWNLOADER_SCAN_DIRS='[{"path":"/music/archive","mountMarker":".hotdownloader-mounted"}]'
HOTDOWNLOADER_DOWNLOAD_MOUNT_MARKER=.hotdownloader-mounted
```

下载目录和附加目录各自需要对应标记。服务不会自动创建标记；只读音乐库也可以检查已存在的标记。
配置标记后，以遍历前后标记仍在根目录内且可读取作为挂载检查依据，允许主动清理大量文件或清空目录。
若数量保护拦截了主动清理，请先确认实际挂载已恢复，在盘内创建标记并配置后重新扫描。
首次扫描尚无数量基线，渐进减少也可能低于阈值，因此需要可靠识别空挂载点时应配置标记。

### 扫描与匹配

支持的音频格式包括：

- MP3、FLAC、M4A/MP4、AAC
- OGG、Opus、APE、WAV
- AIFF、WavPack

扫描依据这些格式的常见扩展名识别文件，不递归扫描符号链接。
正在下载和未完成任务的目标文件不参与匹配。

**增量索引：**

- 首次扫描读取音频标签。
- 此后仅重新读取路径、大小、修改时间或解析配置发生变化的文件。
- 自动完整扫描结果复用 5 分钟，期间只探测根目录和挂载标记；新文件或子目录变化在下次完整扫描时发现。
- 「立即扫描」、监控「立即检查」及「重新扫描并刷新候选」可主动更新索引；同时发起的扫描共用一次执行。
- 自动扫描失败后至少等待 30 秒再尝试；手动扫描可立即重试。
- 匹配通过 SQLite 标题索引检索候选，状态统计只读取 MID 与状态；未变化的记录不重复写入数据库。
- 索引不会修改已有音频文件。

**匹配规则：**

- 标题使用 Unicode NFKC、大小写和空白规范化。
- 歌手按无序集合比较，不比较音质、扩展名或专辑。
- 保留 Live、Remix 等版本文字。
- 优先使用标签，缺失字段才从文件名补充。

以下情况进入「待确认」，可逐曲选择**关联现有文件、下载或忽略**：

- 标签与文件名冲突。
- 存在多个候选文件，或信息不完整。
- 库中存在完全无法识别的文件，无法可靠判断歌曲是否缺失。

无法读取标签的文件会保留警告。
音乐库中的「查看异常文件」按页列出标签读取失败、信息缺失及标签与文件名冲突的文件，支持按路径搜索。

自动匹配成功及手动关联前都会重新打开候选文件，核对文件大小和修改时间；文件不可读或发生变化时保留待处理状态，要求重新扫描。

> 任一配置目录或子目录不可访问时，整轮索引更新和自动补齐都会跳过。
> 服务保留上次完整索引，恢复挂载后再次检查。

### 索引状态

本地音乐库逐目录显示已索引文件数、索引时间、本次读取数量和异常文件数。
状态区分尚未检查、可读取、文件信息需检查和不可访问；错误会显示具体路径与原因。
任一目录失败时整轮索引仍不提交，“已索引”数量保留上次完整扫描的值。
嵌套扫描目录按更具体的根归属计数，同一文件不重复统计；未完成下载继续排除。

## 歌单监控与自动补齐

### 添加监控

1. 在设置页保存可用的 QQ 登录凭据。
2. 打开 Web 版「歌单 → 歌单监控与自动补齐」。
3. 添加 QQ 公开歌单（数字 ID）、个人歌单或「我喜欢」。
   个人歌单可通过「读取我的歌单」选择，并保留目录 ID。
4. 选定自动下载音质和检查间隔，然后启用监控。

Web 版 QQ 歌单详情也提供「添加歌单监控」，自动带入歌单名称、ID 和个人歌单目录。
同一歌单已有监控时会提示编辑已有监控，包括已停用的监控；服务端也会拒绝并发重复添加。
公开歌单按数字歌单 ID 识别重复，个人歌单同时比较歌单 ID 和目录 ID，
「我喜欢」与个人歌单目录 201 视为同一来源。公开来源与个人来源保留各自的访问方式。

### 启停与删除

**检查间隔**为 5–10080 分钟：

- 停用后仍可通过「立即检查」执行一次补齐。
- 停用不取消已入队下载，可在任务页继续暂停、取消和恢复。

扫描和远程歌单查询不占用编辑锁，各监控独立执行，同一监控不会重入。
慢请求期间仍可编辑、启停、删除和逐曲确认；保存前校验配置版本，旧请求的结果不会覆盖新配置或恢复已删除的监控。

监控卡片中的「删除监控」需要确认。删除后停止该监控的后续检查和补齐，
保留已有文件、下载任务、音乐库索引和共享 MID 处理台账。
其他监控仍可继续处理共同的歌曲；重新添加歌单后会沿用已保存的处理决定。

### 补齐与音质

- 首次检查补齐当前缺失歌曲，之后只为新 MID 建立处理记录。
- 相同 MID 在多个歌单中共用状态和任务。
- 每轮最多派发 **20 首**，服务循环每 **10 秒**运行一次。
- 下载并发继续遵守设置页的并发限制。
- 自动补齐在首次入队前，取包含该 MID 且已启用或正在补齐的监控中优先级最高的配置音质，与监控发现顺序无关。
  优先级沿用内置品质顺序（母带、全景声、Hi-Res、FLAC、APE、MP3 等）；目标不可用时再遵守用户的自动降级设置与顺序。
- 单曲及批量手动下载使用当前操作监控的音质，并持久化该选择；其他监控的较高配置不会覆盖它。
- 调整监控音质影响尚未入队的自动补齐歌曲。已有任务保持其音质，已关联、已下载或已忽略的歌曲不会自动升级。
- 手动与自动入口在创建锁内按平台和 MID 去重，未结束的任务（包括暂停、中断）优先复用；并发请求以先创建成功的任务音质为准。
  自动补齐还会复用历史任务，明确重新下载允许为已完成或失败的歌曲创建新任务。
  创建接口复用时返回 `{"outcome":"existing","task":{...}}`，不会重复入队；被复用的手动任务仍由用户控制重试。

**音质设置**保存在服务端：

- 浏览器默认音质仅用于新建表单预填。
- 默认音质为「每次询问」时，必须在表单中另选固定音质。

开启设置页的**自动降级**后：

- 目标音质缺失或获取下载链接失败时，按配置顺序尝试后续音质。
- 仅尝试歌曲提供的品质，直到取得链接或候选耗尽。
- 同一品质的临时网络错误最多请求 3 次；明确的凭据错误停止处理。
- 降级在同一下载任务内完成，不占用监控的额外任务重试次数。
- 实际音质、文件名、大小和保存路径会同步更新。
  目标路径已存在时另存一份，保留其他品质的文件和下载片段。

关闭自动降级后，链接获取失败不会切换品质。

### 待确认歌曲与处理决定

在「查看歌曲」中可勾选待确认歌曲，或选择本页待确认项，再使用「下载所选」或「忽略所选」。
支持跨页选择，每次最多 200 首；切换监控、筛选或搜索条件时清空选择。
提交前需确认共享决定的影响。服务端会重新校验归属和待确认状态，整批保存；
如任意歌曲状态已变化，整批不执行，刷新后重新选择。
批量下载使用当前监控的音质。关联现有文件仍逐曲选择具体路径。
停用监控中的手动下载只处理明确选择的歌曲，不启动同歌单其他歌曲的补齐或重试。

歌曲列表由服务端筛选、搜索和分页，每页 30 首，每 15 秒刷新当前页。
跨页选择会保留，翻页或切换筛选后迟到的旧响应不会覆盖当前列表。

修复异常文件后，对待确认歌曲点击「重新扫描并刷新候选」。候选会重新匹配，但歌曲仍保留待确认状态，需逐曲选择关联、下载或忽略；已经作出的处理决定不会被刷新覆盖。

已关联、已下载、已忽略的决定独立于任务历史：

- 移动或删除文件、清除下载任务，都不触发自动重下。
- 歌单移除歌曲时，不删除本地文件。
- 逐曲「清除决定并重新下载」会清除共享决定，保留已有文件。
  若文件重名，则另存一份。

### 进度与检查历史

监控卡片展示首次补齐进度：

- 以首次成功读取的成员快照为固定范围，后续新增歌曲单独显示逐曲状态。
- 已处理包括已关联、已下载和已忽略；已移出歌单的项不再需要补齐。
- 处理中、待确认和失败分别计数，入队不会增加完成比例。
- 进度为 `(已处理 + 已移出) / 首次快照总数`，空歌单为 100%。
- 旧监控没有首次快照时，在升级后的首次成功检查建立进度基线。

「检查历史」展示最近 **100 轮**，按时间倒序分页并随监控页刷新，重启后仍保留。
历史包含定时检查、立即检查和后续分批补齐/重试，空闲轮次不记录。
每轮记录开始/结束时间、结果、错误说明和以下计数：

| 计数 | 含义 |
| --- | --- |
| 新增 | 本轮歌单成员相对上次成功快照的增量，首轮计入全部成员 |
| 关联 | 本轮自动匹配并关联本地文件的歌曲数 |
| 入队 | 本轮成功提交的新任务和重试数，不代表下载完成 |
| 派发失败 | 本轮因凭据、音质或任务创建/重试错误未能入队的歌曲数 |

各监控独立记录本轮实际完成的关联和派发；其他监控复用同 MID 任务时，不重复计为新入队。
扫描或歌单读取失败也会记录；服务在本轮结束前退出时，重启后标记该轮为中断、统计可能不完整。
删除监控会一并移除其检查历史，保留共享处理台账和任务。

逐曲「查看任务」通过任务 ID 打开独立任务视图，可直接操作该任务；记录已被移除时显示提示。
点击「返回全部任务」恢复完整列表。

### 失败与重启恢复

| 情况 | 处理方式 |
| --- | --- |
| 无可用音质 | 记录状态，等待手动处理 |
| 降级候选的链接全部失败 | 记录候选耗尽，不再由监控自动重试 |
| 网络异常、下载失败或凭据失效 | 分别显示原因；最多自动重试 3 次，分别等待 5、15、60 分钟 |
| 重试次数耗尽 | 停止自动重试，由用户重新处理 |
| 任务记录被移除，或无法确认派发结果 | 进入待确认 |

下载失败时复用原任务。
未监控的手动失败任务不由监控接管重试。

凭据校验超时、连接失败显示为「网络异常」；只有缺失登录凭据或接口明确拒绝时才提示凭据失效。
凭据刷新发生网络、解析或存储错误时保留凭据，恢复后可以再次尝试。

修复网络、登录或存储问题后，可点击「重试失败」。仍存在的监控失败任务复用原任务 ID；本次手动操作重新开始一个最多自动重试 3 次的周期。
被复用的手动任务通过「查看任务」重试；任务记录已移除时使用「清除决定并重新下载」。

服务重启后会继续：

- 未完成的分批补齐。
- 定时检查与尚未耗尽的重试。
- 监控拥有的中断下载。

## 服务接口

服务接口沿用共享核心的 `camelCase` JSON 契约。

### 任务与事件

- `GET /api/tasks`：当前完整任务快照。
- `POST /api/tasks`：提交 `CreateTaskRequest`，成功后返回 `CreateTaskResult`。
- `POST /api/tasks/{id}/pause|resume|retry|cancel|remove`：控制单个任务。取消和删除可传 `{"deleteFile":true}`。
- `POST /api/tasks/remove`：批量删除，传 `{"taskIds":["..."],"deleteFile":false}`。
- `GET /api/events`：SSE。连接后先发送任务与设置快照，再推送任务更新、设置更新和心跳。重连时通过快照同步视图。

事件类型包括 `task-updated`、`task-removed` 和 `settings-updated`。

### 设置与健康检查

- `GET /api/settings`：设置快照。
- `PATCH /api/settings`：字段级合并更新。提交 `changes` 与各字段的 `expected` 原值；同字段冲突返回 HTTP 409 和最新快照。
- `GET /api/settings/default-download-dir`：服务器下载目录。
- `GET /healthz`：服务健康检查，HTTP 服务可响应时返回 HTTP 200 与 `{"status":"ok"}`。

### 音乐与登录

- `POST /api/music/{action}`：查询歌曲、歌单、专辑、歌手、热搜、建议、封面和歌词。参数及结果沿用前端 API 契约。
- QQ 登录状态与凭据操作：
  - `GET /api/login/status`
  - `POST /api/login/qr`
  - `GET /api/login/qr/{id}`
  - `POST /api/login/manual`
  - `POST /api/login/logout`

静态前端资源由同一进程提供。
Web 端输入访问令牌后，通过 HTTP 操作任务，通过 SSE 接收快照和进度。
服务进程管理任务生命周期；进程重启后，手动任务等待恢复，监控拥有的未完成任务自动恢复。

### 监控 API

接口与现有 `/api` 共用访问认证。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/library` | 读取索引状态 |
| POST | `/api/library/scan` | 立即扫描 |
| GET | `/api/library/issues` | 分页读取异常文件，支持路径搜索 |
| GET | `/api/monitors` | 读取监控摘要、状态计数与成员总数 |
| POST | `/api/monitors` | 新建监控 |
| PATCH | `/api/monitors/{id}` | 提交完整配置以修改监控 |
| DELETE | `/api/monitors/{id}` | 删除监控，保留文件、任务与共享台账 |
| POST | `/api/monitors/{id}/check` | 请求立即检查，在服务循环执行 |
| GET | `/api/monitors/{id}/songs` | 分页读取逐曲状态、候选文件、任务与重试信息 |
| GET | `/api/monitors/{id}/history` | 最近 100 轮检查/补齐记录，最新在前 |
| POST | `/api/monitors/{id}/decisions` | 批量下载或忽略当前监控中的待确认歌曲 |
| POST | `/api/library/songs/{mid}` | 修改逐曲处理决定 |

#### 分页查询

歌曲与异常文件接口接受 `page`（从 1 开始）、`pageSize`（默认 30，最多 100）和 `query`。
歌曲搜索匹配标题或歌手，异常文件搜索匹配路径；搜索文本最多 300 字节。
歌曲接口另支持 `filter=all|pending_confirmation|active|done|failed`，筛选后再分页。

```json
{"items":[],"total":0,"page":1,"pageSize":30}
```

歌曲接口统一返回以上分页对象。监控列表以 `memberCount` 返回成员数量，不再附带完整的 `members`、`initialMembers` 数组。
旧客户端需按分页对象读取 `items`；SQLite 索引在启动时自动迁移到版本 2，升级前可按[备份说明](#备份与存储异常)保存数据目录。

#### 监控配置

新建或修改监控时，提交完整配置：

```json
{
  "name": "示例歌单",
  "source": "public",
  "playlistId": "123456",
  "dirid": "",
  "quality": "320kmp3",
  "intervalMinutes": 60,
  "enabled": true
}
```

已有监控可修改名称、音质、间隔和启停状态。

| `source` | 来源 | 参数说明 |
| --- | --- | --- |
| `public` | QQ 公开歌单 | 使用数字 `playlistId` |
| `created` | 个人歌单 | 同时需要 `playlistId` 和 `dirid` |
| `liked` | 我喜欢 | 使用服务端当前 QQ 账号返回的目录 |

歌单读取失败或响应不完整时，保留上次成员快照。

#### 批量处理决定

批量处理向 `POST /api/monitors/{id}/decisions` 提交：

```json
{"mids":["exampleMid1","exampleMid2"],"action":"ignore"}
```

`action` 仅支持 `download` 和 `ignore`，`mids` 为 1–200 项，重复 MID 只处理一次。
成功返回 `{"ok":true,"count":2}`；归属、状态或存储校验失败时整批不写入。
下载请求按原有每轮 20 首的节奏派发，继续遵守并发限制与有限重试。

#### 逐曲处理决定

向 `POST /api/library/songs/{mid}` 提交 `action` 和当前监控的 `monitorId`，服务端校验歌曲归属。
旧客户端仅在歌曲恰好属于一个监控时可省略 `monitorId`；多监控归属必须指定。

| `action` | 操作 | 附加字段 |
| --- | --- | --- |
| `link` | 关联现有文件 | `path`：已索引文件的容器内完整路径 |
| `download` | 下载 | 无 |
| `ignore` | 忽略 | 无 |
| `reset` | 清除决定并重新下载 | 无 |
| `refresh` | 重新扫描并刷新待确认歌曲的候选，保留待确认状态 | 必须提供 `monitorId` |
| `retry` | 手动重试失败歌曲，重新开始有限重试周期 | 无 |

关联文件示例：

```json
{
  "action": "link",
  "monitorId": "当前监控ID",
  "path": "/music/example.flac"
}
```

### 本机前端联调

本机联调时，在两个终端分别运行服务与前端。

### 验证

```bash
cargo test --locked --manifest-path crates/hotdownloader-core/Cargo.toml
cargo test --locked --manifest-path crates/hotdownloader-server/Cargo.toml
cargo clippy --locked \
  --manifest-path crates/hotdownloader-server/Cargo.toml \
  --all-targets -- -D warnings
npm run build
cargo build --locked --manifest-path crates/hotdownloader-server/Cargo.toml
npm run test:monitor-http
npm run test:task-focus
```

监控测试使用合成静音 WAV、MP3、FLAC、虚构歌单和禁止真实下载的执行器，覆盖：

- 增量扫描与匹配冲突。
- 批次入队与跨歌单去重。
- 处理台账、有限重试与重启恢复。
- MP3 ID3v2.4 和 FLAC Vorbis Comments 多值歌手标签、标签与文件名冲突及修改后的增量更新。
- 任务文件的真实 OS 写入错误、SQLite 配额触发的 `SQLITE_FULL`，以及恢复存储后的对账。

仅运行新增的监控可靠性测试：

```bash
npm run test:monitor-reliability
```

崩溃测试由父测试启动独立子进程，在以下持久化边界暂停并强制结束，再启动另一个独立进程恢复：

| 崩溃位置 | 验证结果 |
| --- | --- |
| 任务文件写入前 | 不产生任务，派发中记录转为待确认 |
| 任务文件写入后、入队台账更新前 | 复用已保存任务 ID，补齐台账并恢复入队 |
| 入队台账提交后、引擎注册前 | 保留原任务，重复对账不重复创建 |
| 批量决定事务写入中 | 强制刷新 SQLite 脏页后结束进程；恢复时整批回滚 |
| 批量决定事务提交后 | 恢复时保留整批决定 |

检查点和禁止联网的运行时仅编译进测试程序；发布版不包含这些测试入口。
测试输出中的一个 `ignored` 项是由父测试显式启动的子进程入口，不是未执行的业务场景。
这些测试验证上述明确边界的进程终止恢复，不模拟断电或存储硬件损坏。

共享核心另用本地 HTTP 合成数据和只读文件句柄，验证流写入、缓冲区刷盘失败都不会上报下载完成。
MP3/FLAC 样本已保存在仓库，日常测试无需 FFmpeg；重新生成方式见[音频样本说明](testdata/audio/README.md)。

HTTP 冒烟测试需要 **Node.js 24 或更高版本**（内置 SQLite）。
测试会启动独立的临时服务，并自动清理其合成数据。

监控页面的本地状态回归测试运行 `npm run test:monitor-view`，覆盖轮询生命周期、跨页选择、表单预填、批量操作、文件关联和历史切换。
